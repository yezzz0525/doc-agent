常见错误速查手册

doc-agent 2026-10-04 全部来自真实调试

这份手册的用法：报错时先在浏览器里 Ctrl+F 搜关键字 → 对上号 → 按"怎么修"做。

每一条都是这个项目真实踩过的，不是网上抄的。

第一部分：3 秒定位法

遇到报错别急着改代码，先做这三步，八成的坑两步就能定位。

第 1 步：读异常的第一行，别读堆栈

堆栈有几十行，真正有用的是最上面那行。它已经告诉你"什么东西"和"哪个值"出错了：

异常第一行它已经告诉你
Invalid UUID string: 001-...md#0有东西塞不进 UUID，而且塞的是什么值都写出来了
ClassCastException: A cannot be cast to B某处把 A 强行当成 B，搜 A 出现在哪个类
Port 8081 was already in use不用查，直接换端口或停旧进程

第 2 步：判断是"启动时"还是"运行时"

这决定了往哪个方向查：

  • 启动就报错 → 配置问题（Key 没配、数据库连不上、依赖缺失）→ 看 yaml 和环境变量
  • 点按钮/提问才报错 → 逻辑问题（格式不匹配、表没建、限速）→ 看具体环节的日志

第 3 步：判断是"哪个环节"

本项目一次问答要串行走三段，页面上能看出来：

现象卡在哪一段
一直转圈，连"引用来源"都没出现意图判定 or 向量检索
引用来源出现了，但正文一个字没有回答生成（对话模型）
连"正在思考"都没有，直接报错请求没到后端（后端没启动 / 端口不对）

第二部分：错误速查

A · 模型服务类

模型

429：请求太频繁 / 速率限制

com.openai.errors.RateLimitException: 429: 您的账户已达速率限制，请控制请求频率
java.lang.IllegalArgumentException: Invalid UUID string: ...  ← 这种情况说明是封装层的错

原因：模型服务都有速率上限。三种情况：

  • 并发型：同一时刻只允许 N 个请求。流式回答没结束就发新的 → 必撞（代码里的 GuardedChatModel 就是为此存在的）
  • 频率型：按 QPS/TPM 限速。点「加载文档」时最密集（80 次请求）
  • 超时型：等太久直接抛 Request failed，而不是干脆的 429

怎么判断挂在哪一段：看 meta 事件有没有到。 有引用来源 = 检索已过 = 挂在对话模型；没收到 = 挂在意图判定或检索。

怎么修：

  1. 等 10~20 秒再试（限速窗口通常几十秒）
  2. 等不了就把 application.yaml 里的 doc-agent.embedding.qps 调小（比如 2）
  3. 老撞就换服务商，见本文最后「换服务商」一节
模型

401：令牌已过期 / Token is invalid

{"code":30014,"message":"Token is invalid."}                       ← 硅基流动
InvalidApiKey / {"code":"InvalidApiKey",...}                     ← 百炼
com.openai.errors.UnauthorizedException: 401 ...

原因：Key 没配、拼错了、过期了，或者用了别的服务商的 Key。

两家错误格式完全不同，看格式就知道是哪一家挂的： {"code":30014,...,"message":"Token is invalid."} 是硅基流动； InvalidApiKey / Arrearage 是百炼。

怎么修：本项目需要两个环境变量，缺一个就有一类问题问不了：

DASHSCOPE_API_KEY=百炼Key;SILICONFLOW_API_KEY=硅基流动Key

只有百炼 → 闲聊能答、技术问题 401（检索挂了）；只有硅基流动 → 所有问题都失败。
快速自查：python tools\check_config.py，它会直接告诉你是哪个环节。

模型

模型名写错 → 404 / 模型不存在

原因：各家模型代码写法差异很大，而且免费版和收费版是两个条目。

服务商 / 用途正确写法
百炼 · 对话（当前在用）qwen-flash；报不存在就换 qwen3.8-flash
百炼 · 地址dashscope.aliyuncs.com（少一个 c 会返回 404 HTML 页面）
硅基流动 · 国内站https://api.siliconflow.cn/v1
硅基流动 · 免费向量模型BAAI/bge-m3（写成 Pro/BAAI/bge-m3 就是收费版）
智谱（若换过去）glm-4.7-flash（全小写）

怎么修：拿不准就去服务商官网的模型列表页照抄，注意区分 国际站 / 国内站、免费版 / 收费版。

B · 数据库类

数据库

连不上 PostgreSQL

Connection refused / could not connect / Communications link failure
relation "vector_store" does not exist
Failed to configure a DataSource

原因（按概率排序）：

  1. Docker Desktop 没开 ← 头号原因。双击桌面图标，等右下角鲸鱼变绿
  2. 容器没起：项目根目录执行 docker compose up -d
  3. 刚启动，表还没建出来

怎么修：

docker ps                # 看到 doc-agent-pg 是 healthy 就行
docker compose up -d     # 没起就执行这条
数据库

维度不匹配 dimension mismatch

原因：换了 embedding 模型，但旧索引还在。向量空间变了，新旧向量根本不能放一起比。

怎么修（必须重建索引）：

用 pgvector 的话直接点页面上的「加载文档」； 内存版则要把 data/vector-index.json 和同名 .stats 改名备份（别删），重启后再点一次加载。

数据库

Invalid UUID string: xxx.md#0

原因：pgvector 主键默认是 uuid 类型，而本项目的片段 ID 是 文件名#序号 这种可读字符串（为了让重复加载时覆盖而不是重复插入），塞不进去。

怎么修：建表时指定主键为文本，已在 RagConfig.pgVectorStore() 里加好 .idType(PgIdType.TEXT)。 改主键类型要删表重建：

docker exec -it doc-agent-pg psql -U docagent -d docagent \
  -c "drop table vector_store cascade;"

C · 代码类

代码

ClassCastException: DefaultChatOptions cannot be cast to OpenAiChatOptions

at org.springframework.ai.openai.OpenAiChatModel.createRequest(OpenAiChatModel.java:683)

原因：自己写了个包装器（装饰器）包住 ChatModel， 但漏了转发 getDefaultOptions()。 ChatClient 拿它当底子合并参数，合并出通用类型， 而 OpenAiChatModel 内部直接强转成自己专属的类型 → 崩。

怎么修：包装器里把 getDefaultOptions() 和 getOptions() 一起委托给被包装对象。

通用教训：包装接口时， 凡是和「具体类型」有关的方法一个都不能漏 —— 漏了不报编译错， 只在运行时炸。写完包装器一定要用真实链路跑一次，别只测「能启动」。

环境

Port 8081 was already in use

原因：IDEA 里跑着上一次的后端，新启的撞端口。 你看不到新功能，八成就是它 —— 旧进程跑的还是改动前的代码。

怎么修：在 IDEA 点 Stop 停掉再 Run。或者用另一个端口：

--server.port=8082
环境

Could not resolve placeholder 'XXX_API_KEY'

原因：yaml 里写了 ${XXX_API_KEY}，但环境变量没配。

怎么修：IDEA 右上角运行配置 → Edit Configurations → Environment variables，把 Key 填进去。 注意：CodeBuddy / 某些工具启动的进程会注入 SERVER__PORT 之类的环境变量，Spring Boot 宽松绑定会拿它当配置覆盖掉 yaml。

前端

npm run build 报 MODULE_NOT_FOUND

原因：npm install 中途失败，导致 rollup / esbuild 的 平台专用原生模块没装上（Windows 上是 @rollup/rollup-win32-x64-msvc）。

怎么修：精准补装，不要删整个 node_modules：

npm install @rollup/rollup-win32-x64-msvc
npm install @esbuild/win32-x64

第三部分：不是错误的现象

片段数突然翻倍（319 → 638）

不是 bug。旧版计数器用的是「累加」，重复点「加载文档」就翻倍。 数据其实没重复（向量库用稳定 ID 覆盖了），只是显示错。 现在改成直接数真实条数，已修复。

回答里有 # 号、代码块很乱

不是 bug。模型返回的是 Markdown 源码，交给前端 markdown-it 渲染即可。 没渲染就是样式没加载或 markdown.js 没被调用。

切换向量库后 /api/status 显示 0 个片段

不是 bug。两套向量库的数据各存各的，不会自动迁移。 切换后要重新点一次「加载文档」。

各家免费政策变动频繁，上表以 2026-10 公开信息整理， 以控制台实际显示为准。其他服务商的配置模板已写在 application.yaml 的注释块里，照抄改三行即可。
换对话服务商会自动失效：联网搜索的 enable_search 是百炼特有参数。

第五部分：日常启动顺序

  1. 双击桌面 Docker Desktop，等右下角鲸鱼图标变绿不再动
  2. IDEA 里运行 DocAgentApplication（先 Stop 旧的再 Run）
  3. 前端 npm run dev，打开 localhost:5173
  4. 看一眼左侧知识库状态是不是有片段数

日常使用不用点「加载文档」—— 319 个片段已经在数据库里了，只在换向量模型后才需要重建。
